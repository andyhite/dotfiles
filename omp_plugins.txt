# omp plugins, one per line: <install-source> <plugin-name>
#
# install.sh hands the source straight to `omp plugin install`, unless the
# name field is `name@marketplace` — that form registers `source` as a
# marketplace with `omp plugin marketplace add` first, then installs
# `name@marketplace` through it. A bare source can be a namespaced git
# shorthand (github:owner/repo, optionally #ref — also gitlab:, bitbucket:,
# codeberg:, sourcehut:), a full git URL, or an npm spec; a marketplace source
# is whatever `omp plugin marketplace add` accepts (owner/repo shorthand, git
# URL, or local path).
#
# The name is the second field because omp can't be asked for it: a git
# source doesn't encode a package name (omp resolves it by diffing its own
# plugins/package.json across the install), and the repo is frequently not
# what the package is called. install.sh needs the name to recognise an
# existing install, because omp's lockfile records a version but never a
# source.
#
# Re-running install is how a git-sourced plugin updates: omp follows its
# `bun install` with a `bun update`, which moves the dependency forward. A
# marketplace-sourced plugin has no such update-on-reinstall behavior —
# `plugin install name@marketplace` refuses outright once the id is present —
# so install.sh runs `marketplace update` first, then `plugin install --force`.
#
# A plugin that is link-installed (`omp plugin install ./path`, for developing
# it on this machine) is left alone with a note rather than overwritten — a
# git or marketplace install would replace the symlink with a fetched copy and
# the checkout would quietly stop being what runs.
#
# Everything here installs at user scope rather than into a project. Foreman
# workers are separate omp processes in separate worktrees, and a project-scoped
# plugin would be invisible to them.
#
# Skills are not plugins — cross-agent skills live in agent_skills.txt and are
# installed with the `skills` CLI into ~/.agents/skills instead.

# foreman dispatches peer coding agents into git worktrees via herdr panes,
# and carries their reports and questions back. A worker is a separate `omp`
# in its own pane, worktree, and branch — not an in-process `task` subagent
# sharing this process. Pure omp extension now: registers the foreman_spawn,
# foreman_convene, foreman_roles, foreman_send, foreman_ask, foreman_wait,
# foreman_ls, and foreman_reap tools plus skill://foreman-spawner,
# skill://foreman-worker, and skill://foreman-expert. There is no herdr-plugin
# half anymore (it used to also live in herdr_plugins.txt as
# andyhite/foreman/herdr) and no /foreman:* commands — a spawned worker still
# needs to be running under herdr for its pane to exist, but nothing here
# installs onto herdr itself.
#
# name@marketplace installs through omp's marketplace system: `source` below
# is what `omp plugin marketplace add` registers, `foreman@foreman` is what
# `omp plugin install` then takes. foreman re-added `.omp-plugin/
# marketplace.json` — a self-hosting single-plugin catalog — after a stretch
# where this file did a direct `github:andyhite/foreman foreman` install; that
# was only ever a workaround for a disabledProviders entry that excluded the
# marketplace-installed plugin's own commands and skills along with the real
# ~/.claude content it was meant to exclude, and it's gone now that
# /marketplace install and /marketplace upgrade work again. Before that it was
# `andyhite/foreman  fleet@foreman`, back when the product was named `fleet`;
# a machine still carrying that install has its own copy of /fleet:* and
# should clear it once by hand, then re-run this step:
#   omp plugin uninstall fleet@foreman     # or fleet@omp-fleet, if older still
#   omp plugin marketplace remove foreman  # likewise omp-fleet
andyhite/foreman  foreman@foreman
