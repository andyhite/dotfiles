# omp plugins, one per line: <install-source> <plugin-name>
#
# install.sh hands the source straight to `omp plugin install`. A source can be
# a namespaced git shorthand (github:owner/repo, optionally #ref — also gitlab:,
# bitbucket:, codeberg:, sourcehut:), a full git URL, or an npm spec.
#
# The name is the second field because omp can't be asked for it: a git source
# doesn't encode a package name (omp resolves it by diffing its own
# plugins/package.json across the install), and the repo is frequently not what
# the package is called. install.sh needs the name to recognise an existing
# install, because omp's lockfile records a version but never a source.
#
# Re-running install is how a git-sourced plugin updates: omp follows its
# `bun install` with a `bun update`, which moves the dependency forward. There
# is no separate update command to pair it with.
#
# A plugin that is link-installed (`omp plugin install ./path`, for developing
# it on this machine) is left alone with a note rather than overwritten — the
# git install would replace the symlink with a fetched copy and the checkout
# would quietly stop being what runs.
#
# Everything here installs at user scope rather than into a project. Foreman
# workers are separate omp processes in separate worktrees, and a project-scoped
# plugin would be invisible to them.
#
# Skills are not plugins — cross-agent skills live in agent_skills.txt and are
# installed with the `skills` CLI into ~/.agents/skills instead.

# foreman dispatches peer coding agents into git worktrees via herdr panes,
# and carries their reports and questions back. A worker is a separate `omp`
# in its own pane, worktree, and branch — not an in-process `task` subagent
# sharing this process. Pure omp extension now: registers the foreman_spawn,
# foreman_send, foreman_ask, foreman_ls, and foreman_reap tools plus one
# model-invoked skill://foreman. There is no herdr-plugin half anymore (it
# used to also live in herdr_plugins.txt as andyhite/foreman/herdr) and no
# /foreman:* commands or split skill://foreman-boss/dispatch/worker skills —
# a spawned worker still needs to be running under herdr for its pane to
# exist, but nothing here installs onto herdr itself.
#
# This was `andyhite/foreman  fleet@foreman` until the repo dropped both its
# marketplace and the product name `fleet`: marketplace plugins load through
# omp's claude-plugins provider, so a disabledProviders entry meant to exclude
# real ~/.claude content also excluded the plugin's own commands and skills.
# Direct git installs have no subdirectory syntax, so the plugin moved to the
# repo root to be installable this way, and the product itself was renamed
# `foreman` to match — repo and published plugin share one name now, which is
# why the second field below is a plain `foreman` rather than a distinct
# package name. A machine that installed either marketplace id still has the
# marketplace registered and its own copy of /fleet:*; this step only ever
# adds, so clear the old state once by hand:
#   omp plugin uninstall fleet@foreman     # or fleet@omp-fleet, if older still
#   omp plugin marketplace remove foreman  # likewise omp-fleet
github:andyhite/foreman  foreman

# Model-driven context compression: an extension, not a command pack. omp's own
# auto-compaction replaces the history with one summary once a threshold is
# crossed; this hands the model a `compress` tool and lets it pick which message
# ranges become summaries, so a compressed range stays a labelled block that
# `decompress` restores and `search_context` searches without restoring. Also
# registers `acp_status` and the `/acp` report.
#
# An npm spec, not a github: shorthand like foreman above — the repo .gitignores
# `dist/` and its package.json points omp's extension entry at `dist/index.js`,
# so a git install fetches a tree with no built entry point and loads nothing.
# npm ships the build; it's the only source that works here.
#
# Keep it the only compression extension installed. Two extensions both
# rewriting the message list undo each other's folds, and omp's own compaction
# is a second authority of the same kind — which is why compaction.thresholdPercent
# in omp/agent/config.yml sits above this plugin's own thresholds rather than
# below them. That ordering is load-bearing and documented in README's
# billion-context section; the numbers on both sides have to move together.
#
# Settings live in omp/acp-omp.json, linked to ~/.omp/acp-omp.json by the
# configs step. Note it sets `autoUpdate: false`: upstream defaults to checking
# npm and installing a newer version behind your back, which for a package that
# shipped 17 releases in its first three days means the thing rewriting every
# request changes without a commit here. Re-running this step is the update
# path, same as everything else in this file.
billion-context-omp  billion-context-omp
